# Прогнозирование спроса на новогодний ассортимент MODI

## в разрезе «магазин × товарная подгруппа» для оптимизации первичного распределения

---

### 1. Бизнес-проблема

Розничная сеть MODI ежегодно распределяет новогодний ассортимент по 170+ магазинам на основе экспертной оценки менеджера товародвижения. Решение о первичном распределении принимается в середине октября, когда товар уже на складе, но продажи ещё не начались. Ошибки распределения приводят к двум видам потерь:

- **Недовоз (out-of-stock):** магазин распродал товар досрочно, полка пустует, продажи упущены.
- **Перевоз (overstock):** после 31 декабря непроданный сезонный товар замораживает оборотные средства и требует уценки.

Цель проекта — на основе данных за два новогодних сезона (2024 и 2025) построить статистически обоснованные правила распределения товара и оценить, насколько они точнее текущей практики.

---

### 2. Постановка задачи

**Единица прогноза:** магазин × товарная подгруппа × сезон (ноябрь–декабрь).

**Целевая переменная:** суммарные продажи в штуках за основной сезон.

**Точка отсечки признаков:** 15 октября — модель (или правило) использует только информацию, физически доступную до начала продаж. Это гарантирует отсутствие утечки данных.

**Метрика качества:** WAPE (Weighted Absolute Percentage Error) — взвешенная абсолютная процентная ошибка. Выбрана вместо MAPE, поскольку в данных много ячеек с низкими или нулевыми продажами, на которых MAPE уходит в бесконечность. Дополнительно оценивается bias (систематический пере-/недопрогноз).

**Бейзлайны** (два, для сравнения):

1. **Наивный LFL-прогноз:** факт продаж этого магазина по этой подгруппе за сезон 2024 × коэффициент роста сети.
2. **Fair share:** доля магазина в сетевых продажах × суммарный прогноз по подгруппе.

**Прогноз строится в натуральном выражении (штуках),** поскольку решение о распределении принимается в единицах. Денежное выражение (рубли) используется для приоритизации подгрупп и оценки экономического эффекта (упущенная выручка от дефицита, замороженный капитал в неликвиде).

---

### 3. Данные

**Источник:** 36 недельных выгрузок из учётной системы 1С, подготовленных вручную.

**Период:** по 18 недель на сезон (W40–W05), охватывающих октябрь–январь 2024/2025 и 2025/2026.

**Гранулярность:** магазин × SKU × неделя. Каждая строка содержит:
- остаток на конец недели (шт.);
- продажи за неделю (шт. и руб. с НДС);
- факт отгрузки со склада за неделю (шт.);
- атрибуты магазина (кластер, категория, вместимость, критерий LFL, дата открытия);
- атрибуты товара (категория, группа, подгруппа).

**Объём:** 3 441 294 строки, 172 магазина, 1 572 SKU, 83 товарных подгруппы.

**Обезличивание:** выручка масштабирована коэффициентом в целях конфиденциальности; все относительные величины (доли, ранги, коэффициенты) сохранены.

### 4. Что сделано (Блоки 1–5)

#### Блок 1. Инициализация

Импорт библиотек, настройка путей, функция автоматического разбора имени файла в (год, неделя, сезон) — позволяет загрузить любое количество недель одним циклом без ручного редактирования.

#### Блок 2. Загрузка и консолидация

36 файлов Excel прочитаны в цикле, размечены по сезонам и объединены в единый датафрейм. Итог — 3 441 294 строки × 20 колонок.

#### Блок 3. Первичная проверка целостности

Пять автоматических проверок до любых преобразований:
- полнота недель: 18 + 18 — ОК;
- стабильность колонок между файлами — ОК;
- состав магазинов: 146 (сезон 2024) и 172 (сезон 2025) — рост за счёт открытия новых точек;
- пропуски в ключевых полях (магазин, код товара, подгруппа) — 0;
- типы данных — все количественные поля прочитаны как `float64`, конвертация не требуется.

#### Блок 4. Очистка и преобразование

- **fillna(0):** пустые значения в количественных полях заменены нулями; обоснование подтверждено сверкой на конкретном примере (магазин 11098, SKU УТ-00096255).
- **Дата открытия:** приведена к datetime из смешанного формата 1С (строки `ДД.ММ.ГГГГ` и datetime Excel в разных файлах). Потерь — 0.
- **Нормализация регистра подгрупп:** «Шоколад» и «шоколад» схлопнуты (85 → 76 уникальных).
- **Составной ключ подгруппы:** `категория | группа | подгруппа` — 83 уникальных ключа. Необходим, т.к. имя подгруппы не уникально (например, «наборы» встречаются в 6 группах).
- **Дубликаты:** 0 (ключ: магазин + SKU + сезон + неделя).
- **Справочник магазинов:** собран из данных (не из отдельного файла); стабильность всех 5 атрибутов подтверждена по всем 36 неделям.

#### Блок 5. Конструирование признаков и агрегация

- **Правило `ever_active`:** пара «магазин × SKU» считается в ассортименте, если хотя бы раз за сезон был ненулевой сток, продажа или заказ. Результат: 99.9 % пар активны (145 из 256 470 — вне ассортимента).
- **Флаг дефицита `is_stockout`:** сток = 0 у активной пары. Доля дефицитных наблюдений: 4.3 %.
- **Функциональные окна:** october (W40–W44) — признаки; season (W45–W52) — целевая; january (W01–W05) — оценка неликвида.
- **Агрегация SKU → подгруппа:** понедельная (392 351 строка) и сезонная (24 570 строк).
- **Коэффициент роста:** октябрь 2025 / октябрь 2024 = 0.945 (по 134 сопоставимым магазинам).
- **Признак «новый магазин»:** 21 магазин в сезоне 2024 и 11 в сезоне 2025 не имеют полного прошлого сезона.

### 5. Ключевые методологические решения

| Решение | Обоснование |
|---------|-------------|
| Анализ на уровне подгруппы, а не SKU | Решение о распределении принимается по товарной матрице; SKU обновляется между сезонами, а подгруппы сопоставимы |
| Продажи ≠ спрос: коррекция на дефицит | Если магазин распродал товар досрочно — его продажи занижают реальный спрос. Флаг `is_stockout` фиксирует такие недели |
| Косвенное правило `ever_active` вместо справочника ассортимента | Справочник планового ассортимента недоступен; ограничение зафиксировано |
| Коэффициент роста — по октябрю, до начала сезона | Исключает утечку данных: величина известна на 15 октября |
| Прогноз без ML | Бюджет времени и текущий уровень компетенций; ML (Ridge-регрессия) заложена как опциональное расширение по контрольной точке |

### 7. Учёт обратной связи по предыдущей версии проекта

Проект является развитием более ранней работы (1 квартал, праздники 14.02 / 23.02 / 08.03), по которой была получена обратная связь научного руководителя. Ключевые замечания и их статус:

| Замечание | Как учтено |
|-----------|-----------|
| Определение OOS как «остатки < продажи» — прокси, а не реальный дефицит | Заменено на `is_stockout`: сток = 0 при активной паре (магазин × SKU). Долю дефицита считаем на уровне магазин × подгруппа × неделя |
| Флаги риска через глобальный топ-N одинаковы для всех магазинов | Риск считается на уровне магазин × подгруппа (доля недель с дефицитом), а не через глобальный список |
| Нормы рассчитаны только по неделям с продажами > 0 — завышает среднее | Агрегация идёт по всем неделям активной пары, включая нули |
| Нет ретроспективной проверки (train/test) | Ядро проекта: прогноз на сезон 2025 по правилам из 2024, сравнение с фактом через WAPE |
| Нет денежного выражения | Продажи выгружены и в штуках, и в рублях. Рубли — для приоритизации и оценки экономического эффекта |
| Коэффициент роста глобальный | Рассчитан по сопоставимым магазинам; сегментация по кластерам и категориям запланирована в EDA |
